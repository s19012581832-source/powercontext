# 《江湖·记忆》验证样例与运行证据

本文给出一组**可逐步执行**的验证样例，覆盖：① seekdb 检索真实生效；② PowerContext 跨会话记忆真实生效；③ Dify 主流程端到端体验。

---

## A. 初始状态与准备

1. 已按《运行说明》启动：Dify（导入 DSL）、seekdb 网关（`:8001`）、PowerContext（`:8000`）。
2. 玩家使用默认 `player_id = demo-player-001`（全新，PowerContext 中尚无该玩家记忆；seekdb 已灌入 34 条武侠设定）。
3. 验证服务可达：
   ```bash
   curl http://127.0.0.1:8001/health      # seekdb 网关
   curl http://127.0.0.1:8000/health/live  # powercontext
   ```

## B. 验证样例 1：seekdb 世界观设定检索（应用功能层）

**目的**：证明 seekdb 在"生成剧情"之前真实参与检索，且结果被用于互动。

**操作（直接打网关，等价于 Dify 内 `seekdb-桥段素材匹配` / `seekdb-武学设定检索` 节点）**：
```bash
curl -s -X POST http://127.0.0.1:8001/v1/seekdb/match_scene \
  -H 'Content-Type: application/json' \
  -d '{"query":"我想去一个能听秘闻、遇高人的热闹地方","n_results":2}'

curl -s -X POST http://127.0.0.1:8001/v1/seekdb/retrieve \
  -H 'Content-Type: application/json' \
  -d '{"collection":"skills","query":"后山遇到白猿，想学一门轻功身法","n_results":3}'
```

**预期表现**：
- `match_scene` 命中「江湖酒楼」「山神庙夜话」等"社交/悬疑"类桥段。
- `retrieve(skills)` 命中「凌波微步」（逍遥派轻功）、「北冥神功」等，且距离（distance）随语义相关度递减。

**实际结果（见 `verification/evidence/seekdb_proof_output.txt`）**：脚本 `verification/seekdb_proof.py` 在干净环境重跑得到真实命中，确认 seekdb 承担"武侠设定检索"职责。

**技术作用记录**：Dify 的 `seekdb-桥段素材匹配` 与 `seekdb-武学设定检索` 两个 HTTP 节点把检索结果注入 LLM 提示词，使剧情引用真实存在的门派/武功，保证世界观一致。

## C. 验证样例 2：PowerContext 跨会话记忆（应用功能层）—— 核心爽点

**目的**：证明"换一个新对话，NPC 仍记得你"真实成立。

**步骤 1（会话一：写入记忆）**：
```bash
# 创建玩家空间（idempotency_key = player_id）
SCOPE=$(curl -s -X POST http://127.0.0.1:8000/v1/scopes \
  -H 'Content-Type: application/json' \
  -d '{"title":"江湖记忆-玩家","summary":"玩家角色卡","idempotency_key":"demo-player-001"}' \
  | python -c 'import sys,json;print(json.load(sys.stdin)["scope_id"])')

# 写入：玩家偷了少林掌门玉佩，与少林结怨
curl -s -X POST http://127.0.0.1:8000/v1/memory/remember \
  -H 'Content-Type: application/json' \
  -d "{\"scope_id\":\"$SCOPE\",\"kind\":\"decision\",\"text\":\"玩家曾偷走少林掌门玄苦的玉佩，与少林结下梁子；师出逍遥派，习得凌波微步。\",\"reason\":\"初始化玩家状态\"}" \
  | python -c 'import sys,json;print("records=",len(json.load(sys.stdin)["records"]))'
```

**步骤 2（会话二：新对话，召回记忆）**—— 模拟玩家重新打开对话，只说「我回少林寺看看」：
```bash
curl -s -X POST http://127.0.0.1:8000/v1/context/prepare \
  -H 'Content-Type: application/json' \
  -d "{\"scope_id\":\"$SCOPE\",\"query\":\"少林寺 掌门 玉佩\",\"max_bytes\":4000}" \
  | python -c 'import sys,json;d=json.load(sys.stdin);print("status=",d.get("status"));print("content=\n",d.get("content"))'
```

**预期表现**：`status: ready`，`content` 中包含"偷走少林掌门玄苦的玉佩/与少林结下梁子"。在 Dify 中，LLM 节点会据此生成：「你这偷玉佩的小贼，竟还敢回少林？」式回应——即"被记住"。

**实际结果（见 `verification/evidence/powercontext_proof_output.txt`）**：脚本 `verification/powercontext_proof.py` 重跑得到 `status: ready` 并成功召回，证明跨会话记忆真实生效。

**技术作用记录**：Dify 的 `创建/获取玩家记忆空间` → `召回玩家记忆` → `保存玩家记忆` 三个 HTTP 节点，把 PowerContext 的 scope/remember/prepare 串成闭环，记忆持久化在服务端，跨会话复现。

## D. 验证样例 3：Dify 主流程端到端体验

**目的**：证明应用可接收输入并返回结果，且两大技术被调用。

**操作**：在 Dify 应用界面输入：
```
我去后山练剑，遇见一只通灵白猿，它似要传授我武学。
```

**预期表现**：
1. `创建/获取玩家记忆空间`：返回 scope_id。
2. `召回玩家记忆`：若此前写过记忆则带回历史；否则 `empty`（正常）。
3. `seekdb-桥段素材匹配`：命中「后山秘境」「古墓奇遇」等桥段。
4. `seekdb-武学设定检索(skills)`：命中「凌波微步」「北冥神功」等。
5. LLM 续写一段武侠剧情，合理融入上述设定，并在结尾抛出新选择。
6. `保存玩家记忆`：把本次行动写入 PowerContext。
7. `输出剧情`：把 LLM 文本返回界面。

**复现顺序与恢复初始状态**：
- 端到端依赖连续操作；要重复验证，只需在 Dify 新建一个对话（或改 `player_id`）。
- 要清空某玩家记忆：调用 `DELETE/POST` 对应 scope 或重建 scope（PowerContext 提供 scope 管理接口），详见官方文档。
- 要重置 seekdb 设定：删除 `jianghu_seekdb.db` 后重启网关即重新灌入。
