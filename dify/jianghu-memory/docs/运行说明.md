# 《江湖·记忆》运行说明

> 赛题：**Just for Fun——用 Dify 做一个好玩的智能应用**
> 技术栈：**Dify（必选，核心编排） + OceanBase seekdb（武侠世界观设定检索） + PowerContext（跨会话玩家记忆）**
> 适用 Dify 版本：≥ 0.15（DSL schema `version: 0.1.5`，advanced-chat）

---

## 1. 作品创意与玩法

**《江湖·记忆》** 是一个会"记住你"的武侠文字冒险。你扮演初入江湖的少侠，用**一句话**描述自己的行动或选择（如「我去后山练剑，遇见一只白猿」「我偷了少林掌门的玉佩」），AI 说书人据此续写一段有武侠味、越聊越离奇的冒险。

核心爽点来自 **PowerContext 的跨会话记忆**：你关掉对话、重新开一个，NPC 依然记得你上次干过的事——「你这偷玉佩的小贼，又回来了？」。这与赛题背景示例"一个会记住玩家恶作剧的 NPC"直接呼应。

**体验方式**：在 Dify 应用界面直接与说书人对话即可，无需额外前端。

---

## 2. 技术分工（Dify 与指定技术如何各司其职）

| 技术 | 角色 | 在应用中的实际作用 |
|------|------|------------------|
| **Dify** | 核心编排 | 输入处理（START）、模型调用（LLM 续写）、工具调用（4 个 HTTP 节点）、结果输出（ANSWER）；承担整条对话链路 |
| **seekdb** | 应用功能层 · 横向世界知识 | 存储并检索"武侠世界观设定库"（门派/武功/桥段/NPC）。每次生成前做**向量+语义检索**，保证剧情世界观一致、素材丰富（节点：桥段素材匹配、武学设定检索） |
| **PowerContext** | 应用功能层 · 纵向玩家状态 | 保存并复用"玩家角色卡与剧情进度"。每回合**写入**玩家行动、**召回**历史记忆，实现跨会话记得玩家（节点：创建空间、召回记忆、保存记忆） |

> 二者分工清晰、缺一不可：seekdb 让你"世界更真实"，PowerContext 让你"被记住"。

## 3. 运行环境

| 组件 | 版本 / 说明 |
|------|------------|
| 操作系统 | Linux（推荐 Ubuntu 22.04+；Dify 与 pyseekdb 的生产部署环境） |
| Docker + Docker Compose | 部署 Dify 社区版 |
| Python | ≥ 3.11（seekdb 网关与 PowerContext 均需要） |
| Dify | 社区版，docker 部署 |
| seekdb | `pyseekdb>=1.4`（Python SDK，嵌入式模式，无需独立服务端） |
| PowerContext | `powercontext[cli,server]`（本地 Server，默认 SQLite） |
| 模型服务 | 任意 Dify 支持的 LLM（OpenAI / 通义 / 本地 Ollama 等），在 Dify 内绑定 |

> ⚠️ Windows 仅可用于编写与代码审计；**seekdb 嵌入式引擎（pylibseekdb）在 Windows 不自动安装**，因此本应用的实际运行与验证请在 Linux 上进行。本文所有命令均按 Linux 给出。

## 4. 模型与密钥配置（使用占位值，不提交真实密钥）

在 Dify 中：

1. **模型供应商**：在 `设置 → 模型供应商` 添加你的 LLM（如 OpenAI、通义千问、Ollama）。DSL 中默认写的是 `openai / gpt-4o-mini`，导入后请在 LLM 节点把模型改成你已接入的模型。
2. **环境变量**（Dify 应用 → `环境变量`）：
   - `PC_URL`：PowerContext 服务地址，默认 `http://127.0.0.1:8000`
   - `SEEKDB_URL`：seekdb 网关地址，默认 `http://127.0.0.1:8001`
   - `PC_TOKEN`：PowerContext 鉴权 Token（本地默认无鉴权可留空；启用服务端鉴权后再填）
3. **会话变量**：`player_id`（默认 `demo-player-001`），用于隔离不同玩家的记忆；真实使用时可由前端/接口传入用户标识。

## 5. 完整部署步骤

### 5.1 部署 Dify（如使用官方 docker 部署）
```bash
git clone https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
docker compose up -d
# 访问 http://localhost:5001 完成初始化
```

### 5.2 启动 seekdb 网关（提供世界观设定检索 API）
```bash
cd dify/jianghu-memory/seekdb-gateway
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# 首次运行会自动：拉起 pyseekdb 嵌入式引擎 + 下载默认向量模型 + 灌入武侠设定
python app.py
# 监听 0.0.0.0:8001，访问 /health 验证
```
- 网关启动即幂等初始化世界观数据（见 `data/lore_data.json`，含门派/武功/桥段/NPC 四类共 34 条）。
- 如需自定义端口：`SEEKDB_PORT=8001 SEEKDB_PATH=./jianghu_seekdb.db python app.py`

### 5.3 启动 PowerContext（提供跨会话记忆 API）
```bash
# 需 Python 3.11+ 与 uv
pip install uv
uv tool install --force "powercontext[cli,server] @ git+https://github.com/oceanbase/powercontext.git@master"
powercontext server run
# 默认监听 127.0.0.1:8000（SQLite），可用 curl http://127.0.0.1:8000/health/live 验证
```
> 启用服务端鉴权后，把 Bearer Token 填入 Dify 的 `PC_TOKEN`，并在 HTTP 节点 `Authorization` 头中加入 `Bearer {{#env.PC_TOKEN#}}`（本 DSL 默认无鉴权）。

### 5.4 导入 DSL 并配置
1. Dify → `工作室 → 导入 DSL`，选择 `dify/jianghu-memory/dsl/jianghu_memory.yaml`。
2. 在应用 `环境变量` 中确认 `PC_URL` / `SEEKDB_URL` / `PC_TOKEN` 指向 5.2/5.3 实际地址。
3. 在 LLM 节点绑定你已接入的模型。
4. 点击 `预览` 或直接打开应用界面即可体验。

### 5.5 应用入口
Dify 应用界面（Web）即为入口；也可通过 Dify 的 API/WebApp 嵌入到其他页面。

## 6. 网络与资源条件

- seekdb 网关**首次启动需联网**以下载默认向量模型（onnxruntime + 中文句向量），之后可离线。
- Dify 调用 `PC_URL` / `SEEKDB_URL` 需网络互通（通常同机或同内网）。
- 资源：Dify 全套约需 4C8G；seekdb 网关与 PowerContext 均为轻量进程，数百 MB 内存即可。

---

## 7. 已知限制与异常处理

- **Windows 不支持嵌入式 seekdb 引擎**：本应用运行请在 Linux。
- **首次向量模型下载**：若内网无法访问模型源，可提前在有网环境缓存后拷贝，或改用自建 embedding 服务（修改 `seekdb-gateway/app.py` 的嵌入方式）。
- **记忆为空属正常**：新 `player_id` 或无关查询时，PowerContext `prepare` 可能返回 `status: empty`，流程照常进行，不会伪造历史。
- **HTTP 节点超时**：若 seekdb/PowerContext 未启动，Dify 会报节点失败；请先确认两者 `/health` 正常。

## 8. 复用来源与改动说明

- **Dify DSL 结构**参考自公开示例 [`dzh-gitcode/dify-workflows`](https://github.com/dzh-gitcode/dify-workflows)（娱乐游戏目录的对话流），已按本作品重写全部节点、提示词与接入逻辑。
- **seekdb** 使用官方 `pyseekdb` SDK（嵌入式模式），网关为自研轻量 Flask 服务。
- **PowerContext** 使用官方 HTTP API（`/v1/scopes`、`/v1/memory/remember`、`/v1/context/prepare`），调用方式参照官方[快速开始](https://powercontext.oceanbase.io/zh/docs/develop/api-quickstart/)。
- 所有外部依赖均为开源组件，未引入额外付费服务（模型除外，按需自选）。
